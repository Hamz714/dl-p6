**Muon smoke test (exp_018, on the 011 network):**
- **Optimiser:** one `MuonAdamW` class with one `step()` per update. It applies Muon to the 83 hidden weight matrices: Nesterov momentum 0.95, 5 Newton–Schulz steps, conv kernels reshaped to 2-D, lr 0.02·√max(1, rows/cols). Everything else (biases, norm gains, time-embedding MLP, input and output convs) gets AdamW at lr 1e-3. The EMA stays warm-started.
- **Built-in version:** torch 2.14 does ship `torch.optim.Muon`, but it only handles 2-D weights and is a separate optimiser, so the class is self-contained.
- **CPU checks:** the AdamW half matches `torch.optim.AdamW` to 6e-8. Newton–Schulz produces singular values of 0.67–1.13, the intended range.
- **Loss at update 300:** 0.240 vs 0.264 for a 300-update 011 run on identical batches. The mean over updates 200–300 is 0.256 vs 0.289 (−11%). It was stable, with no spikes.
- **Speed cost:** 5.3 vs 8.7 updates/s under the same contention (−39%). I then batched the Newton–Schulz step by matrix shape, which cut the optimiser step from 87 to 33 ms (AdamW is 5 ms). Expect the full Muon run to take noticeably longer than 28 minutes.
